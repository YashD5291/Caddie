<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SCK framework → coordinator actor | `stopCapture()` is an external async call of unbounded latency; the actor must not be held hostage by it |
| App lifecycle → capture engine | `NSApp.terminate` can cut the process at any moment during finalize |
| Filesystem | The `.mov` must be left in a playable state on every exit path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-08 | Denial of service | `executeStopAndTranscribe` | mitigate | 5-second bounded stop via the task-group race; transcription is enqueued regardless, so a wedged SCK cannot strand a meeting in "Processing…" |
| T-19-09 | Tampering (data integrity) | video file at meeting end | mitigate | `stopVideo()` runs unconditionally on all four teardown paths and joins the start task first, so no capture is ever orphaned; the engine's fragmented `.mov` + `deinit` finalize are the second and third safety nets |
| T-19-10 | Repudiation | app quit during recording | accept | `NSApp.terminate` does not await the shutdown `Task`; finalize may not complete. Accepted because the fragmented `.mov` stays playable minus at most ~10 s (VID-07, hardware-verified in 18-04); blocking quit on `finishWriting` is explicitly rejected |
| T-19-11 | Information disclosure | orphaned `.mov` after meeting deletion | accept | Phase 20 owns `deleteAudio` extension and the disk guard; documented as a transient limitation in 19-04's README task and in the phase summary |
| T-19-SC | Tampering | SPM package installs | accept | No package-manager installs in this plan; `project.yml packages:` unchanged |
</threat_model>
