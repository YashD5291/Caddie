<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SCK framework queue → coordinator actor | `onFirstFrameHostTime` and `onStreamStopped` arrive on framework/writer queues and cross into the actor via `@Sendable` closures that hop with `Task { await self?… }` |
| macOS TCC → app | A denied Screen Recording grant surfaces as a real `start()` throw; the app must degrade, never retry-loop or spoof |
| Capture engine → filesystem | The vended engine writes only to the `AudioFileManager.videoPath(for:)` URL the coordinator hands it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-04 | Denial of service | `startVideoInner` | mitigate | Video start runs in a separate `videoStartTask`, so a slow or TCC-prompt-blocked SCK setup cannot stall the coordinator actor and delay audio start, stop, or device switching |
| T-19-05 | Repudiation | video failure paths | mitigate | Every failure calls `surfaceVideoError` (log at `.error` + user-visible channel); no silent catch exists in any video path, enforced by the "no `handle(.recordingFailed` in video paths" and "audio is still recording x2" grep gates |
| T-19-06 | Information disclosure | capture start | mitigate | The coordinator only vends an engine when `AppState` injected a factory, which happens only when the opt-in gate is on (19-04); tests inject mocks so `make test` can never capture the screen |
| T-19-07 | Tampering | `RecordingState.swift` | mitigate | No new reducer states or events; the reducer file must show zero diff (acceptance gate in Task 1) |
| T-19-SC | Tampering | SPM package installs | accept | No package-manager installs in this plan; `project.yml packages:` unchanged |
</threat_model>
