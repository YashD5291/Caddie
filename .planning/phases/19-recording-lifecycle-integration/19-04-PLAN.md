<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User intent → capture | `ScreenRecordingSettings.isEnabled` is the only thing that decides whether a capture engine is ever constructed |
| macOS TCC → app | A denied grant must surface as a visible, honest message, never as a silent no-op |
| Coordinator actor → MainActor UI | `onVideoError` crosses via a `Task { @MainActor in … }` hop, as every other coordinator callback does |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-19-12 | Information disclosure | `AppState.initialize()` | mitigate | The factory is constructed only inside `if ScreenRecordingSettings.isEnabled`; with the key absent the coordinator's dependency is nil and every video path is inert — screen capture cannot start by accident |
| T-19-13 | Repudiation | user-facing error copy | mitigate | Dedicated `lastVideoError` with "Screen recording stopped — audio was saved" instead of reusing "Last recording failed"; shown in the `.recording` branch too, so the user learns during the meeting |
| T-19-14 | Elevation of privilege | `Permissions.screenRecording` | accept | The status is logged for diagnostics only and never gates construction; TCC remains the sole authority and denial is handled as a normal degrade |
| T-19-SC | Tampering | SPM package installs | accept | No package-manager installs in this phase; assert with `git diff --stat -- project.yml` showing no change to the `packages:` block |
