<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| macOS TCC → app | Screen Recording grant is the OS access control for any capture; this plan adds no capture, only the gate that decides whether capture is ever attempted |
| UserDefaults → app | `screenRecordingEnabled` is a `Bool` read from the user's own defaults domain; no other process writes it |
| App → filesystem | `videoPath(for:)` composes a path from an internally generated meeting id under `~/Library/Application Support/Caddie/audio/` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-01 | Information disclosure | `ScreenRecordingSettings` | mitigate | `defaultEnabled = false` and `object(forKey:) as? Bool ?? default` — an absent key can never read as enabled, so capture is opt-in (VID-01 semantics) |
| T-19-02 | Tampering | `AudioFileManager.videoPath(for:)` | mitigate | meetingId is app-generated (`RecordingState.generateMeetingId`), never user-supplied; path is composed via `appendingPathComponent` under the app-support directory only — no traversal input |
| T-19-03 | Information disclosure | Test doubles | mitigate | `MockScreenRecorder` never touches ScreenCaptureKit, so `make test` can never capture the developer's screen; the real engine is unreachable from tests in this phase |
| T-19-SC | Tampering | SPM package installs | accept | No package-manager installs in this plan or phase — `project.yml packages:` is unchanged (GRDB, SimplyCoreAudio, AXSwift, Sparkle, FluidAudio). Package Legitimacy Gate is not applicable; asserted by an acceptance criterion in 19-04 |
</threat_model>
